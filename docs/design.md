# 山野赛事惠农结算 · 领域设计

略阳越野赛现场的消费券既可购买农产品，也可抵扣文旅套餐。参赛人、商品批次、摊位、核销凭证、文旅服务与补贴资金必须处在**同一条可逐笔对账的链路**上：优惠在核销当场确定承担方，退款在发生当场入账，不依赖赛后表格补算。

## 1. 参与方与权限

| 参与方 | 可见范围 | 关键动作 |
| --- | --- | --- |
| 游客与参赛者 | 本人持有的券、订单、退款、履约状态 | 当场查询券适用范围与退款去向 |
| 本地农产品商户 | **仅本商户**（含其名下各摊位）的交易 | 入驻、绑定摊位、核销、查看结算明细 |
| 文旅服务商 | 仅本机构的文旅服务订单与履约 | 服务核销、履约确认、退款受理 |
| 赛事运营方（县域运营方） | 全场只读监控与规则配置 | 商户/摊位审核、券批次规则发布、异常处置 |
| 财政部门（补贴出资方） | 补贴资金池与逐笔承担台账 | 出资、对账、红冲复核 |
| 主办单位 | 汇总成效报表 | 认定新增销售、复购、未履约服务 |

商户之间数据行级隔离：权限判定以 `merchant_id` 为准，摊位只是商户在某一时段的经营位置，不作为数据归属边界。

## 2. 实体与结算链路

```
participant（参赛人/游客，参赛号绑定支付身份）
   │ 持有
   ▼
voucher（消费券：批次/面额/资金来源/适用范围/状态）
   │ 下单时按订单行分摊、预占
   ▼
order ──< orderLine（每一行绑定一个责任主体）
              ├── 农产品行 → productBatch + stall(归属 merchant)
              └── 文旅行   → travelService + 履约节点
   │ 支付/核销
   ▼
redemption（一次性核销凭证：动态码 + 幂等键）
   │ 触发逐笔登记
   ├──> subsidyEntry（补贴台账分录：承担方、金额；退款时生成负向红冲分录）
   └──> fundPool（补贴资金批次，按出资方设池，核销减额、红冲回补）
   │ 服务类订单继续
   ▼
fulfillment（履约记录：预约 → 到场确认）
   │ 退款
   ▼
refund（退款单：部分退款、自付原路退、补贴红冲回补，幂等）
```

要点：

- **订单按行拆分**：一张订单含多个商户/摊位/服务时拆为订单行，每行独立计算优惠、独立生成核销凭证，避免跨商户混算。
- **券按行分摊**：一张券用于多行时，各行分摊补贴额之和等于券面额；券不跨订单重复使用。
- **台账只追加**：`subsidyEntry` 不可修改，更正一律以负向（红冲）分录体现，保留凭证关联。
- **交易归属商户不归属摊位**：`stall` 记录商户与场地的绑定关系及生效时段，换摊是新增一条带时间戳的绑定，历史订单归属不变。

## 3. 券与核销的状态机

券状态原子流转，防止多终端同时使用同一张券：

```
issued ──下单──▶ frozen（预占，绑定订单+终端）──核销成功──▶ redeemed
  ▲                  │
  └────超时/撤单──────┴──异常──▶ released（回到可领用池/作废）
 redeemed ──退款──▶ 券不复活；补贴额红冲回补资金池（不退现金）
```

- **动态一次性核销码**：码短期有效、单次失效，不承载权益本身；截图重放在第二次校验时被拒。
- **幂等键**：核销与退款请求均携带客户端请求 ID（nonce），服务端对 `(请求类型, nonce)` 建唯一索引；网络重试返回首次结果，不重复入账。
- **并发控制**：券状态流转用乐观锁（CAS 版本号）或行锁；数据库层面对 `(voucher_id, order_line_id)` 建唯一约束，兜底双终端并发。
- **部分退款**：退款单关联原核销凭证，自付与补贴**同比例**退回；累计退款 ≤ 原交易金额，退款幂等键防止重复退。

## 4. 异常场景的责任与退款规则

| 场景 | 农产品交易 | 文旅服务（未履约） | 券与补贴处理 |
| --- | --- | --- | --- |
| 选手退赛（个人原因） | 已交付的不回溯 | 按退改条款退：个人自付原路退回；手续费按条款归服务商 | 未核销券作废或按规则延期；已核销补贴不退现金，未履约部分红冲回补资金池 |
| 暴雨等不可抗力致活动缩短 | 已成交不回溯 | 未履约服务全额退（自付原路），或改签为新服务/新券 | 补贴部分红冲回补；若主办方决定补偿，补偿从主办资金池另行出资，逐笔登记承担方 |
| 商户临时换摊 | 交易随商户连续，不因换摊产生退款 | 不适用 | 换摊期间先挂起该摊核销权限，新摊位绑定生效后恢复；绑定变更全程留痕，错摊入账被拒绝 |

退款去向对游客当场可见，区分两条线：

1. **个人自付部分**：原路退回支付渠道，展示渠道流水号。
2. **券补贴部分**：不发现金，按资金来源红冲回补至原 `fundPool`（恢复该批次额度），或按规则换发新券；游客端展示"补贴已退回××资金批次/已换券"。

## 5. 查询、对账与成效口径

- **游客端（当场可查）**：每张券的适用范围（农产品 / 指定文旅套餐 / 满减门槛）、各订单状态、退款金额与去向、文旅服务的预约与履约状态。
- **商户端**：仅本商户名下各摊位的交易、核销、退款与待结算金额。
- **财政台账**：每笔优惠对应一条 `subsidyEntry`，可回答"每笔优惠由谁承担"（财政券资金 / 主办资金池 / 商户让利，按出资规则逐笔拆分），并与资金池余额双向轧平。
- **新增销售**：以参赛人/游客身份打标的赛期成交，对比商户赛前同期基线（或以非参赛客群为对照），只把可归因增量计入；同时记录补贴撬动比 = 成交总额 / 补贴额。
- **赛后复购**：同一身份在赛后 N 天内于入驻商户（含线上渠道）再次下单的订单数与金额，与赛期初单通过 `participant_id` 串联。
- **已收款未履约文旅服务**：文旅订单行已支付且券已核销、但无到场履约确认记录的清单，区分"已预约未到场"与"未预约"，供主办与服务商跟踪履约或退款。

## 6. 不做的事

- 不以静态截图、券码图片作为核销依据。
- 不在赛后用表格批量补算优惠承担与退款。
- 不允许台账分录被物理修改或删除（只能红冲）。
- 不向商户暴露其他商户或游客维度的汇总数据。
