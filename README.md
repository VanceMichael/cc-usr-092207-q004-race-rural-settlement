# 山野赛事惠农结算

核对山野赛事中的消费券、农产品销售与旅游服务结算。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例（当前为 v2）。参与方包括县域赛事运营方、本地农产品商户、文旅服务商、游客与参赛者、补贴资金管理人员（财政）与主办单位。

资料所依据的领域事实如下：

- 赛事现场设置特色农产品展销区，农产品按批次上架销售
- 消费券既可购买农产品，也可抵扣文旅套餐
- 活动通过消费券和旅游路线推介连接在地产业，形成体育、农业和文旅融合路径
- 选手退赛、暴雨迫使活动缩短、商户临时换摊等异常情形必须现场可结算
- 截图复用、多终端并发、订单拆分、部分退款都不能造成重复补贴

## 同一条可对账链路

参赛登记 → 消费券（出资批次与适用范围）→ 商户与摊位（含换摊时段）→ 商品批次 → 订单与拆单 → 支付 → 核销凭证 → 文旅服务履约 → 退款 → 补贴资金台账。参赛人、批次、摊位、凭证、文旅服务和补贴资金因此落在同一链路，每笔优惠都能从订单追到券、追到出资批次、追到台账分录。

## 异常情形与退款去向

- **选手退赛**：已交付农产品保持有效；未履约文旅按自付款原路退回、券抵扣退回补贴资金池处理；券额度注销，不得对同一服务再次计补。
- **暴雨缩短活动**：文旅服务按已履约/未履约拆分；已收款未履约订单批量进入退款队列，逐单列明原路退回金额与补贴池回收金额；不可抗力不由商户倒贴。
- **商户临时换摊**：交易归属商户主体，换摊只登记摊位时段变更，旧凭证按成交时摊位快照留档，不重开凭证、不二次补贴。

退款一律回写原核销凭证：自付部分原路退回支付渠道，补贴部分退回资金池，不以现金退给游客；部分退款按比例回收补贴，累计回收不超过该凭证已核销补贴。

## 防重复补贴控制

- 核销只认服务端签发并签名的凭证，手机截图不构成核销依据
- 券号唯一约束 + 状态机与行锁/条件更新，多终端并发仅一笔成功
- 核销与退款请求带幂等键，重试返回同一凭证同一结果
- 拆单时券抵扣写明分摊，子单分摊之和等于原抵扣额
- 退款、撤销、冲正必须关联原凭证号，禁止以新券补偿旧单
- 补贴台账分户守恒：余额 = 预付 − 实付 + 回收

## 可见范围

- **游客**：现场扫码即可查清券的适用范围（可用商户、品类、文旅套餐、有效期）和每笔订单退款去向
- **商户**：经服务端授权后只能接触本 merchant_id 的交易，越权访问在接口鉴权层拒绝
- **财政与主办单位**：全链路只读，按出资批次取得对账分录与汇总
- 参赛人、游客、复购顾客全程使用化名或哈希标识

## 对账四问

1. **每笔优惠由谁承担**：核销凭证关联出资批次与台账分录，逐笔列明承担方及联合出资比例
2. **新增销售**：赛期订单对照非赛期同口径基线，自付与含券金额分列，避免把补贴算作收入
3. **后续复购**：以匿名标识统计赛后窗口期的复购人数、复购率与金额，不与赛期新增销售重复
4. **已收款未履约旅游服务**：按服务商、套餐、服务日期汇总笔数金额，并标注应原路退回与应回补补贴池金额

## 本地校验

`src/domain.js` 校验领域标识、版本、参与方、事实、约束，并强制检查链路环节、三类异常情形、关键防重控制、可见范围规则和四类对账报表是否齐备。运行 `npm test` 即可检查示例资料能稳定读取且关键规则不缺失。仓库不保存账号、密钥、连接串或真实身份信息。
